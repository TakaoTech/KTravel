# :password-strength

Password strength estimation for Kotlin Multiplatform.

Given a password, it returns a score from 0 to 4, an entropy estimate in bits, and symbolic feedback
about what makes the password weak. KTravel uses it to rate the password protecting an exported
travel archive, but the module knows nothing about that: it depends on nothing but the Kotlin
standard library.

## Credit

This is a Kotlin Multiplatform port of
**[nbvcxz](https://github.com/GoSimpleLLC/nbvcxz)** by Adam Brusselback (GoSimple LLC), MIT licence,
ported from commit `8ecc8a6` (version 1.5.1). nbvcxz is itself a Java reimplementation of
**[zxcvbn](https://github.com/dropbox/zxcvbn)** by Dropbox, whose scoring semantics — the 0-4 scale
and its thresholds — this module keeps.

The word lists in `dictionaries/` are nbvcxz's own, unmodified.

Licence text: [`LICENSE-nbvcxz.txt`](LICENSE-nbvcxz.txt). Every ported file names the Java class it
came from in its header.

**Updating from upstream**: pull the new `src/main/java/me/gosimple/nbvcxz/` and
`src/main/resources/dictionaries/`, diff against commit `8ecc8a6`, and apply the delta by hand. The
dictionaries are drop-in replacements; the sources are not, because of the deviations below.

## Usage

```kotlin
val evaluator = NbvcxzPasswordStrengthEvaluator()

val strength = evaluator.evaluate(
    password = "correct horse battery staple",
    // Values an attacker plausibly knows. Treated as dictionary entries of their own, so a password
    // built out of them is priced accordingly.
    userInputs = listOf("takaotech", "user@example.com"),
)

strength.score        // 0..4, zxcvbn semantics
strength.entropy      // bits
strength.warning      // PasswordWarning? — what is wrong
strength.suggestions  // List<PasswordSuggestion> — what would help
```

The scale, unchanged from zxcvbn:

| Score | Meaning |
|-------|---------------------------------------------------------------|
| 0 | too guessable — risky |
| 1 | very guessable — protects only against throttled online attacks |
| 2 | somewhat guessable — protects against unthrottled online attacks |
| 3 | safely unguessable — moderate protection from offline attacks |
| 4 | very unguessable — strong protection from offline attacks |

**Call it off the main thread.** The first `evaluate` materialises roughly 170,000 dictionary
entries; the result is cached for the lifetime of the process and instances are safe to share, but
that first call is not free.

Constructor parameters cover the knobs upstream exposes — minimum entropy, maximum length, whether
edit-distance matching runs, and the timeout on the exhaustive combination search — all with
upstream's defaults.

## Supported targets

JVM, Android, iOS (arm64, simulator arm64, x64), macOS arm64, watchOS (arm64, simulator), Linux (x64, arm64), Windows (mingw x64), JS and Wasm/JS.

macOS x64 is deliberately absent: it is a deprecated Kotlin target scheduled for removal.

This breadth is only possible because the port has no dependencies. In particular there is **no
Compose in this module**: Compose Resources, which would have been the obvious way to ship the word
lists, does not cover the Linux and Windows native targets. Adding any dependency here means first
checking it publishes artifacts for all of the above.

(The build does apply the Compose detekt rule plugin, but only because the shared `detekt.yml`
carries a `Compose` rule section and detekt rejects the config without the plugin that owns it. It
is a static-analysis plugin, not a dependency of the module.)

## How it differs from nbvcxz

The algorithm and its numbers are unchanged — the test suite asserts entropy against values captured
from upstream 1.5.1, and the port reproduces all of them to six decimal places. What changed is the
plumbing that could not cross to Kotlin Multiplatform:

| Upstream | Here | Why |
|---|---|---|
| `ResourceBundle` + `feedback_*.properties` | `PasswordWarning` / `PasswordSuggestion` enums | Localisation belongs to the caller; KTravel resolves these against its own `strings.xml`. |
| `getResourceAsStream` for the word lists | Constants generated by the `generateDictionarySources` Gradle task | No multiplatform resource API covers every target. |
| `BigDecimal` | `Double` | No multiplatform `BigDecimal`; the thresholds involved do not need the precision. |
| `System.currentTimeMillis()` for the search timeout | `TimeSource.Monotonic` | Multiplatform, and monotonic is the correct clock for a deadline. |
| `java.util.regex.Pattern` | `kotlin.text.Regex` | Same syntax for the patterns used. |
| Guess types and crack-time estimates | not ported | Only the command line tool used them. |
| `Match.getDetails()` | not ported | Built a human-readable dump for the same tool. |

Two upstream behaviours are deliberately preserved even though they look wrong, because changing
them would move every entropy figure away from the reference:

- The upper-case bonus drops the last **two** characters when testing for a trailing capital, not
  one (`DictionaryMatch.uppercaseEntropy`).
- Edit-distance matching runs against the whole password, so a long passphrase can be matched as a
  single near-miss of one dictionary word. This is why `correct horse battery staple` scores 1 here
  and in upstream, despite being four words long.

## Dictionaries

`dictionaries/` holds the six upstream word lists, about 1.3 MB uncompressed:

| File | Entries | Ranking |
|--------------------|---------|-----------------------------------|
| `passwords.txt` | 100,002 | ranked, most common first |
| `surnames.txt` | 40,583 | ranked |
| `english.txt` | 18,091 | ranked |
| `eff_large.txt` | 7,776 | unranked — all entries share a rank |
| `female-names.txt` | 3,815 | ranked |
| `male-names.txt` | 1,004 | ranked |

`generateDictionarySources` turns each into one Kotlin object of string constants, chunked to stay
under the JVM's 65535-byte limit for a single constant and escaped for backslashes, quotes and
dollar signs. It runs automatically before every compilation; `DictionaryTest` asserts the entry
counts and the handful of entries that need escaping, so a regression in the generator fails the
build rather than quietly shifting scores.

The generated sources add roughly 1.3 MB to compilation and, on `wasmJs`, to the bundle.
