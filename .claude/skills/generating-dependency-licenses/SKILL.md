# Dependency licenses in KTravel

The list behind `ui/settings/LicensesPage.kt` is generated by the AboutLibraries Gradle plugin. No
part of it is written or committed by hand.

## What it covers

The metadata is collected from **`:composeApp`'s classpaths**. Project dependencies are not reported
as entries, but the graph walk continues into their own dependencies, so every `gunzou` module is
included through `:gunzou-navigator` and `:gunzou-navigator-client`. `:password-strength`
contributes nothing: it depends on the standard library alone.

Out of scope on purpose: the dependencies `:androidApp` declares for itself. Collection is
per-project and there is no aggregation across modules, so covering them would mean either a
synthetic resolvable configuration in `:composeApp` or moving the declarations down into
`composeApp/androidMain`. Neither was wanted.

`exportLibraryDefinitions` — the task with **no variant attached** — is the one that runs. It
collects the union of every compile and runtime classpath, which is what makes the `targets` array
on each library meaningful. Do not set `export.variant`: that would filter the task down to a single
target.

## How it reaches the app

```
:composeApp:exportLibraryDefinitions
  → build/generated/aboutLibrariesResources/files/aboutlibraries.json
  → registered as a Compose resource directory of androidMain / jvmMain / iosArm64Main / iosSimulatorArm64Main
  → Res.readBytes("files/aboutlibraries.json") in LicensesPage.kt
```

Two constraints are load-bearing, both discovered the hard way:

- **A Compose custom resource directory replaces the directory of the source set it is registered
  on**, it does not extend it. Registering it on `commonMain` silently empties `drawable/` and
  `values/`, and the build fails on unresolved `Res.drawable.*` accessors. It is declared on the
  four platform source sets instead; every target assembles `commonMain` plus its own, so the file
  is packaged exactly once everywhere. A new Kotlin target needs its source set added to that list.
- **The output directory must not be `generated/aboutLibraries`.** The Android side of the plugin
  writes `generated/aboutLibraries/<variant>/res` under that name, and a Compose resource directory
  that holds another task's output is an implicit dependency Gradle refuses to run.

## Remote lookups: release CI only

| | local build | release CI |
|---|---|---|
| `-Pktravel.licenses.fetchRemote` | absent | `true` |
| `offlineMode` | `true` | `false` |
| `fetchRemoteLicense` | `false` | `true` |
| `GITHUB_TOKEN` | unset | job-level `secrets.GITHUB_TOKEN` |

`offlineMode` governs the download of the **SPDX license texts** as well as the GitHub API calls, so
a development build lists licenses by name and leaves their text empty. That is expected — it is not
a bug to chase. Only the artifacts built by `.github/workflows/release.main.kts` carry the complete
data; that file is generated into `release.yaml`, so edit the `.main.kts` and re-run it
(`kotlin release.main.kts`) rather than the YAML.

`gitHubApiToken` feeds the plugin's `license` endpoint lookups, which is what fills in the licenses
that are not plain SPDX ids (roughly four of the nine in this project). A 401 from
`https://api.github.com/rate_limit` in the build log means the token was sent and rejected, not that
the wiring is broken.

## Optimized Resource Shrinking / AGP 9

The Android side of the plugin also generates a `res/raw/aboutlibraries.json` into `:composeApp`'s
resources. Nothing reads it — the screen reads the Compose resource, which lands in `assets` — so
R8's optimized resource shrinking, on by default since AGP 9, drops it from the release APK. That is
the wanted outcome, and it is why the `res/raw/keep.xml` the AboutLibraries README recommends is
**deliberately absent**. Add it only if the loading path ever changes to the Android-only
`Libs.Builder().withContext(context)`, and name the file for the module
(`aboutlibraries.keep.xml`, not `keep.xml`) so it does not collide during resource merging.

## Verifying

```bash
./gradlew :composeApp:exportLibraryDefinitions       # writes build/generated/aboutLibrariesResources/…
./gradlew :composeApp:jvmTest --tests '*LicensesPage*'
./gradlew :androidApp:assembleRelease                # then check the APK
unzip -l androidApp/build/outputs/apk/release/*.apk | grep aboutlibraries
```

The release APK must contain `assets/composeResources/…/files/aboutlibraries.json` and **no**
`res/raw/aboutlibraries.json`. To exercise the CI path locally:

```bash
GITHUB_TOKEN=… ./gradlew :composeApp:exportLibraryDefinitions -Pktravel.licenses.fetchRemote=true
```

`LicensesPage` has a stateless overload taking `Libs?`, which is what the test drives with an inline
fixture — never assert against the real generated list, it changes on every dependency bump.
